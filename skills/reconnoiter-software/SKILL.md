# Reconnaissance Sessions

Use source code, documentation, and existing tests to orient, generate hypotheses, locate observation points, and explain established behavior. Treat every model, requirement, document, and source reading as a potentially fallible map.

Establish default logging and the application index with exploratory-session-log before substantive work, unless the user explicitly opts out. Use research-domain to reuse cached domain context or perform the initial five-minute research when none exists. Further research requires an explicit caller request; continue with recorded gaps when the timebox expires. If research-domain is unavailable, follow the same cache-first and timebox boundaries using available sources. Documentation and repository access help but are not prerequisites.

Start at an entry point relevant to the mission and identify available behavioral surfaces, control points, observation points, and initial variables. Choose a small faithful experiment likely to teach something; extend the working model as observations reveal paths and boundaries.

When the focused skills are available, draw on charter-exploration, map-touch-points, identify-variables, and observe-behavior as questions arise. Record what remains inferred or inaccessible and how that limits subsequent experiments.

Record discoveries promptly in the raw session log and link reusable context from the application index. Use research to guide behavioral probes and revise the working model when evidence disagrees.
